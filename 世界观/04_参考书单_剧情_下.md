### 1.4 喜剧技法（写作用）

| 技法 | 说明 | 本项目怎么用 |
|---|---|---|
| 身份误会 | 把强者当骗子 | 教皇微服、洪荒客把菜单当战书 |
| 规则反噬 | 店规伤到自己人 | 护院在店里只能挨打 |
| 一本正经荒诞 | 用严肃语气说离谱事 | 万象簿记账式吐槽 |
| 重复变奏 | 同一笑点换条件 | 每次开业劫都有"砸场" |
| 反差萌 | 强者做小事 | 域主排队等位 |
| 群像互怼 | 伙计之间拆台 | 大厨 vs 账房 |
| 冷面笑匠 | 主角不笑，别人笑 | 东家永远面无表情 |
| 节奏三拍 | 铺垫—升级—收 | 每章一个笑点 |
| 悲喜交替 | 笑完给一刀 | 开业成功后的坏消息 |
| 语言错位 | 各域黑话互不理解 | 跨域客人的翻译灾难 |

### 2.5 建设流写作要点

| 要点 | 说明 |
|---|---|
| 需求先行 | 先有"客人要什么"，再有"建什么" |
| 六步闭环 | 图纸→备料→招工→施工→验收→开业 |
| 每一步都能出事 | 材料涨价、工人跑路、邻居抗议 |
| 数字要具体 | 多少钱、多少天、几个人 |
| 验收要卡人 | 系统不放过不合格工程 |
| 收益要延迟 | 开业不等于赚钱，先亏三章 |
| 扩张要有代价 | 分店越多，管理越难 |
| 升级要五件事 | 口碑、材料、人、店规、开业劫 |
| 失败要留痕 | 烂尾工程成为后续伏笔 |
| 建设即人物 | 每建一处，带出一个人的故事 |
